# Ймовірність треку в чипах за часом суперника (map-кейс)

Дата: 2026-08-05. Гілка: opponent-assistant (стадія 3 опонент-асистента).

## Проблема

Коли скан екрана 3 дає лише карту (трек невідомий), чипи показують усі треки
карти без жодного сигналу, який із них імовірніший. Але часто за часом
суперника «очевидно», який це трек — гравець хоче бачити цю очевидність як
відсоток у чипі й порядок чипів за спаданням.

## Рішення

Суто **візуальний** сигнал у чипах таба асистента. Жодного впливу на
`narrow_track`, `win_chance`, `auto_pick` чи оверлей: песимістична логіка
лишається як є, рішення приймає гравець кліком по чипу.

### Розрахунок — AssistantService.track_probabilities

`track_probabilities(track_ids: list[int], opponent_time: int) -> dict[int, float]`

1. Для кожного треку — **медіана останніх 50 чистих** (без 👎) заїздів
   будь-яким авто. Трек без заїздів пропускається.
2. Вага треку: `exp(−(d / TAU)²)`, де `d = |opponent_time − median| / median`,
   `TAU = 0.10` (узгоджено з запасом `NARROW_MARGIN` ±10%).
   Точний збіг → 1.0; відхилення 10% → ~0.37; 20% → ~0.02.
3. Нормалізація ваг до суми 1.0 — повертаються частки.
4. Порожній dict, якщо: немає `opponent_time`, або медіана порахована менш
   ніж для **двох** кандидатів (єдиний трек з даними давав би оманливі 100%).

### Дані — RacesRepository / RacesService

`get_recent_clean_times(track_id: int, limit: int = 50) -> list[int]` — часи
останніх `limit` чистих заїздів трека будь-яким авто
(`WHERE time > 0 AND bad_timing = 0 ORDER BY created_at DESC`).
Медіана рахується в Python у сервісі асистента (`statistics.median`).

### UI — assistant_tab._refresh_chips

Лише для map-кейсу (`e.track_candidates` порожній, чипи походять з
`_map_tracks`); OCR-чипи не змінюються:

- чипи сортуються за спаданням ймовірності; треки без даних — у кінці,
  в поточному порядку;
- текст чипа: `«Назва · 79%»` (округлення до цілого відсотка); суфікс « ?»
  виведеного фікса зберігається після відсотка;
- на чипах з відсотком тултіп: пояснення, що це близькість часу суперника до
  медіани моїх часів на треку — новий ключ `assistant.track_prob_chip_tooltip`
  в `ui_lang` (en + uk);
- якщо `track_probabilities` повернув `{}` — поведінка як зараз (без цифр,
  поточний порядок).

## Крайні випадки

- Немає часу суперника гонки → без відсотків, як зараз.
- Дані лише в одного/нуля треків карти → без відсотків.
- Округлені відсотки можуть не давати в сумі 100 — прийнятно.
- Вибраний (checked) чип після сортування може бути не першим — прийнятно.

## Тести (tests/test_assistant.py, tests/test_session_manager.py не чіпаємо)

- Частки: ближчий до медіани трек отримує більшу частку; сума ≈ 1.
- Точний збіг медіани домінує над треком на відстані 10%+.
- `{}` без часу суперника; `{}` коли медіана є лише в одного треку.
- Медіана: викид у вибірці не зсуває результат (медіана, не середнє).
- Репозиторій: ліміт 50 останніх, брудні заїзди (`bad_timing=1`) і
  `time=0` відфільтровані, всі авто разом.

## Поза скоупом

Показ у оверлеї, автофікс треку за порогом, вплив на підбір авто чи
загальний шанс, ймовірності для OCR-кандидатів (`track_candidates`).
