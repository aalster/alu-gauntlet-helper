# Порівняння: субпроцес → движок у пам'яті (ctypes)

Реалізація: `screen_recognition/tesseract_api.py` — libtesseract-5.dll з
портативного бандла вантажиться в процес один раз, движок на мову (eng/rus)
ініціалізується один раз і перевикористовується. `ocr._run_ocr` — єдина точка
запуску. pytesseract видалено з залежностей (субпроцесного шляху більше
немає). Інсталятор без змін (tesseract/ вже їде з exe).

| Метрика (48 скрінів) | Субпроцес (after-fix) | Движок у пам'яті |
|---|---|---|
| Всього часу | 342s | **33.2s (10.3×)** |
| Середній екран | ~7.1s | **0.69s** |
| Медіана / максимум | ~8s / 15.4s | **0.70s / 1.8s** |
| OCR-викликів | 2534 | 2534 (без змін) |
| Не розпізнано | 0 | 0 |
| Розпізнані дані | — | **ідентичні до одного** |
| Тестовий набір (179 тестів) | 154s | **19.6s** |

Вартість одного виклику: ~120–300 мс → ~20 мс (немає старту процесу,
завантаження traineddata, запису тимчасового PNG).

Подальші оптимізації (менше викликів: піксельні гейти, геометрія для
before-акордеона) тепер дадуть економію з ~0.7 с, а не з ~7 с — доцільність
переоцінити за відчуттями в застосунку.
